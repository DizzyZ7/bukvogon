# БуквоГон — Product & Architecture Design

## 1. Цель продукта

БуквоГон — русскоязычная соревновательная браузерная игра на скорость и точность печати. Игрок набирает общий для всех участников текст; корректный прогресс по тексту преобразуется в движение машины по трассе. Основной цикл должен быть понятен за несколько секунд, но иметь долгосрочную мотивацию через рейтинг, статистику, гараж, достижения и сезоны.

Проект вдохновляется жанром typing-race, но не копирует бренд, ассеты, тексты или интерфейс TypeRush/Nitro Type. У БуквоГона должны быть собственные игровые правила, визуальная система и экономика.

## 2. Продуктовые принципы

1. Free-игрок получает настоящую игру, а не демо.
2. Pro за 300 ₽/мес открывает соревновательный контур, а не преимущество в самой печати.
3. Ranked всегда server-authoritative: клиент сообщает ввод, сервер определяет валидный прогресс и итог.
4. Платная косметика и гараж не влияют на фактическую скорость машины в Ranked.
5. Все участники конкретной ranked-гонки получают одинаковый текст и одинаковые правила.
6. Русский язык — first-class: знаки/мин как основной показатель, WPM — дополнительный.
7. Правило `е/ё` на старте: в Casual допускается нормализация `е ↔ ё`, в Ranked текст требует точного символа. В настройках тренировки пользователь сможет выбрать поведение.

## 3. Модель доступа

### Free

Free должен поддерживать высокий retention и социальное распространение:

- неограниченные Casual-гонки;
- быстрая игра с людьми и ботами;
- приватные комнаты по ссылке/коду;
- одиночная тренировка;
- базовая статистика: CPM, WPM, accuracy, ошибки;
- профиль;
- уровни аккаунта и XP;
- достижения;
- гараж и косметика;
- ежедневные задания;
- просмотр публичных профилей;
- просмотр общего описания Ranked и собственного последнего квалификационного результата, но без участия в официальном рейтинге.

Free нельзя ограничивать таймером, энергией или количеством гонок.

### Pro — 300 ₽/месяц

Pro открывает:

- Ranked matchmaking;
- placement-гонки сезона;
- MMR и дивизионы;
- официальный глобальный лидерборд;
- сезонный лидерборд;
- рейтинг друзей;
- историю изменения рейтинга;
- percentile и позицию относительно игроков;
- расширенную статистику по буквам, биграммам, ошибкам и стабильности;
- сезонные косметические награды;
- Pro-бейдж в профиле;
- приоритетный доступ к экспериментальным соревновательным режимам.

Pro не дает:

- ускорения машины;
- множителя MMR;
- повышенной точности;
- дополнительных попыток исправлять ошибки;
- более простых текстов;
- скрытых преимуществ в матчмейкинге.

## 4. Почему Ranked платный

Платный Ranked — это не продажа силы, а подписка на организованную соревновательную инфраструктуру: серверные проверки, рейтинговую историю, сезонную систему, лидерборды, античит и статистику. Free сохраняет основной fun loop, а Pro монетизирует игроков с наиболее высокой вовлеченностью.

Для снижения барьера в будущем можно проводить бесплатные Ranked Weekend/Trial события, но базовая модель MVP — Ranked доступен только при активной подписке.

## 5. Игровые режимы MVP

### Casual Race

- 2–6 участников;
- 45–90 секунд целевой длительности;
- комната может заполняться ботами;
- одинаковый текст;
- результат: место, CPM, WPM, accuracy, errors;
- XP и мягкая валюта;
- не влияет на MMR.

### Ranked Race

- только авторизованные Pro-игроки;
- 4–6 реальных игроков по возможности;
- боты не влияют на MMR и по умолчанию не используются после выхода из закрытого beta;
- фиксированный ranked ruleset;
- точное совпадение `е/ё`;
- paste/IME anomaly detection;
- результат валидируется сервером;
- MMR обновляется только после финализации матча.

### Practice

- соло;
- выбор сложности/длины текста;
- результаты не влияют на лидерборд;
- позже: тренировка слабых букв и биграмм.

## 6. Метрики печати

Основной показатель — CPM (characters per minute), потому что для русского языка он интуитивнее и не зависит от условной длины слова.

Дополнительно:

- WPM = корректные символы / 5 / минуты;
- Accuracy = корректные нажатия / все учитываемые нажатия;
- Raw CPM;
- Errors;
- Correction count;
- Consistency — вариативность скорости по временным окнам.

Для Ranked итоговая позиция определяется прогрессом по тексту и временем завершения. Если время матча закончилось — сравнивается доля корректно набранного текста, затем accuracy, затем время достижения последнего валидного символа.

## 7. Ranked и рейтинг

MVP использует сезонный рейтинг 1000 как стартовое значение после placement. В доменной модели рейтинг абстрагирован интерфейсом `RatingEngine`, чтобы без миграции gameplay менять реализацию.

На первом этапе рекомендуется multiplayer-Elo/placement-based алгоритм:

- матч интерпретируется как упорядоченный список мест;
- каждое место сравнивается с остальными участниками как набор виртуальных парных исходов;
- коэффициент изменения уменьшается после достаточного числа матчей;
- disconnect/forfeit считается поражением только после grace-period;
- подозрительные матчи получают status `review` и не обновляют MMR до валидации.

Дивизионы MVP:

- Новичок
- Бронза
- Серебро
- Золото
- Платина
- Алмаз
- Мастер
- Грандмастер

Конкретные пороги должны быть конфигурацией, а не захардкоженной UI-логикой.

## 8. Лидерборды

Лидерборд Pro:

- current season rating;
- all-time peak rating;
- top CPM с минимальной accuracy threshold;
- friends;
- country/region позже, когда появится достаточная аудитория.

В публичном профиле Free-пользователь может видеть, что у Pro-игрока есть ранг, но полнофункциональная таблица лидеров требует активной подписки.

## 9. Экономика и гараж

В MVP две сущности:

- Coins — бесплатная игровая валюта за гонки/задания/достижения;
- Cosmetics — машины, корпуса, колеса, следы, номерные рамки, эмоции победы.

Все машины внутри гонки имеют одинаковую игровую физику. Визуальные параметры не меняют движение, hitbox или результат.

Покупка Pro не должна напрямую выдавать MMR. Допустимы сезонные косметические награды и небольшие бонусы к XP аккаунта, если они не влияют на соревновательный результат.

## 10. Античит

Ranked должен быть server-authoritative с первого релиза.

Минимальный набор:

- запрет paste/drop/программной подстановки в игровое поле;
- timestamp sequence validation;
- проверка невозможных burst-последовательностей;
- проверка монотонности progress;
- rate-limit WebSocket events;
- server-side text id + immutable text snapshot для матча;
- match nonce;
- duplicate/replay protection;
- anomaly score для подозрительных результатов;
- separate validation state: `valid`, `review`, `rejected`.

Нельзя блокировать игрока только по высокому CPM: сильные машинисты существуют. Решение должно опираться на паттерн событий, а не на одно число.

## 11. Архитектура

Монорепозиторий:

```text
apps/
  web/          Next.js + TypeScript
  api/          FastAPI
packages/
  contracts/    shared schemas / generated client types
infra/
  docker/
docs/
```

Backend домены:

- `identity` — user/profile/auth integration;
- `entitlements` — Free/Pro и срок подписки;
- `races` — комнаты, матч, участники, результаты;
- `typing` — нормализация и валидация ввода;
- `ranked` — eligibility, rating, divisions, seasons;
- `leaderboards` — projection/read model;
- `economy` — XP, coins, cosmetics;
- `anti_cheat` — event validation/anomaly decisions.

PostgreSQL хранит durable state. Redis используется для matchmaking, lobby presence, race state cache и pub/sub между realtime workers.

## 12. Subscription domain

Backend не должен спрашивать платежного провайдера при каждой попытке входа в Ranked. Платежный adapter через webhook обновляет локальный entitlement:

```text
FREE
PRO_ACTIVE
PRO_GRACE
PRO_EXPIRED
```

`can_play_ranked(user)` истинно только для `PRO_ACTIVE` и, если бизнес-правило разрешит, короткого `PRO_GRACE` после временной ошибки автопродления.

Цена MVP: 300 ₽/месяц. Провайдер оплаты подключается отдельным adapter'ом, чтобы не связывать доменную модель с конкретной кассой.

## 13. Realtime flow

1. Клиент получает access token.
2. Для Ranked API проверяет entitlement.
3. Matchmaking помещает игрока в очередь.
4. Match service создает race и immutable rules snapshot.
5. WebSocket отдает countdown и text snapshot.
6. Клиент отправляет typing events/progress acknowledgements.
7. Сервер валидирует последовательность и обновляет authoritative progress.
8. После finish/timeout сервер фиксирует результат.
9. Anti-cheat помечает результат.
10. Только `valid` ranked match обновляет rating transactionally.
11. Leaderboard projection обновляется после commit рейтинга.

## 14. Ошибки и деградация

- Потеря WS: короткий reconnect grace-period с resume token.
- Redis недоступен: новые realtime-матчи не создаются, durable данные не повреждаются.
- PostgreSQL недоступен: матч может быть остановлен до старта; ranked результат не считается без durable commit.
- Webhook оплаты дублируется: обработка idempotent по provider event id.
- Истек Pro во время уже начатого Ranked: матч разрешается завершить; новый Ranked не начинается.

## 15. Тестирование

Backend:

- unit tests для entitlement/rating/text validation;
- property tests для rating invariants;
- integration tests PostgreSQL/Redis;
- WebSocket race tests;
- idempotency tests платежных webhook.

Frontend:

- component tests typing input;
- unit tests метрик;
- Playwright flow Free → Casual;
- Playwright flow Free → Ranked paywall;
- Playwright flow Pro → Ranked.

## 16. MVP boundaries

В первый релиз не входят:

- кланы;
- турниры за реальные деньги;
- marketplace между игроками;
- мобильные приложения;
- voice/chat;
- сложная 3D-физика;
- NFT/криптовалюта;
- pay-to-win upgrades.

Первый критерий успеха: новый пользователь заходит, начинает Casual меньше чем за минуту, понимает связь печати с движением машины, завершает гонку и видит желание сыграть еще раз. Pro-пользователь дополнительно получает честный Ranked с понятным изменением рейтинга и лидербордом.
